# 한의원AI로컬구축

**macOS에서 Apple 내장 로컬 LLM을 테스트하려고 만든 실험용 앱입니다. 현재 상태에서는 실전용으로 쓰지 말고, macOS 로컬 LLM 테스트 용도로 사용해 주세요.**

원래 Notion AI 기반으로 구성해 둔 한의원 AI 자동화의 Notion 링크를 Codex에게 주고, “이걸 로컬 앱으로 만들어 달라”고 해서 빠르게 만든 프로젝트입니다. 처음부터 실전 제품 수준으로 설계·검증한 것은 아니고, 일단 돌아가게 만든 MVP에서 시작했습니다. 이후 SwiftUI 네이티브 화면과 Apple AI·음성 전사 연결을 붙여 시험했습니다.

**앱은 돌아갑니다. 하지만 실전용 AI 품질은 아직 나오지 않습니다.** 설문·저장·전사·초안 생성 흐름이 동작하는 것과, 생성된 기록이 사실을 정확하게 보존하는 것은 별개입니다. 현재 목적은 모델의 출력과 실패를 직접 확인하고, 무엇을 맡길 수 있고 없는지 실험하는 것입니다.

앱 이름은 **`한의원AI로컬구축.app`**이며 SwiftUI 앱과 Python·SQLite 로컬 서버를 사용합니다. 저장소·Swift 모듈 이름은 `clinic-ai`·`ClinicMac`입니다. AFM 3 Cloud·AFM 3 Cloud Pro는 로컬 모델과 비교하기 위한 선택 경로이며, 이를 선택하면 클라우드에서 처리됩니다. 설치형 배포·공증을 마친 제품도 아닙니다.

## macOS 27의 내장 LLM과 Cloud AI — 바이브 코딩용 소개

macOS 27은 2026년 9월 14일 정식 배포가 시작됐습니다. 이 프로젝트는 macOS의 AI를 앱에 연결해 보려는 개발·바이브 코딩 실험입니다. [Apple 배포 안내](https://www.apple.com/newsroom/2026/09/major-updates-for-apples-software-platforms-are-now-available/)

**AFM 3는 Apple Foundation Models의 3세대 모델군**입니다. 아래는 Apple의 공식 소개를 요약한 것으로, 이 앱의 품질 시험 결과와 구분합니다.

| 모델 | 실행 위치 | 공개 규모 | 어떤 모델인가 |
| --- | --- | --- | --- |
| **AFM 3 Core** | 기기 내부 | **3B · 30억 파라미터** | 기본 온디바이스 dense 모델 |
| **AFM 3 Core Advanced** | 지원 기기 내부 | **총 20B · 200억, 활성 1~4B · 10억~40억** | 요청에 따라 일부 가중치를 활성화하는 멀티모달 모델 |
| **AFM 3 Cloud** | Private Cloud Compute(PCC) | 해당 소개 글에 파라미터 수 미공개 | 속도·효율·성능의 균형을 지향하는 서버 모델 |
| **AFM 3 Cloud Pro** | PCC | 해당 소개 글에 파라미터 수 미공개 | 복잡한 추론·에이전트 도구 사용을 겨냥한 상위 서버 모델 |

‘가변 20B’는 **총 규모가 변한다는 뜻이 아니라 총 20B 중 활성 부분이 1~4B로 달라진다**는 뜻입니다. B는 10억 파라미터이며 GB 단위 메모리 용량이 아닙니다. 이 모델군에는 별도로 이미지 생성·편집용 **ADM 3 Cloud**도 있습니다. [Apple AFM 3 소개](https://machinelearning.apple.com/research/introducing-third-generation-of-apple-foundation-models)

### Apple이 발표한 성능

- **AFM 3 Core**: 일반 텍스트 선호도에서 이전 세대 대비 **45.6% 대 23.3%**.
- **AFM 3 Core Advanced**: 활성 1B의 음성 합성 평가에서 **4.15/5점**, 기존 시스템은 3.87점. 받아쓰기 선호도는 **44.7% 대 17.6%**.
- **AFM 3 Cloud**: 이전 서버 모델과의 텍스트 선호도 **64.7% 대 8.7%**.
- **AFM 3 Cloud Pro**: AFM 3 Cloud 대비 텍스트 응답 만족도 약 **10% 상대 개선**.

이는 Apple의 자체 평가이며 정확도나 SOAP 합격률이 아닙니다. 특히 Core Advanced의 음성 평가를 임상 문서 작성 성능으로 해석하지 않습니다. 발표 글의 평가 시점과 현재 앱 시험도 다릅니다. [Apple 평가 설명](https://machinelearning.apple.com/research/introducing-third-generation-of-apple-foundation-models#evaluation)

### 모델과 API, 이 앱의 연결은 다릅니다

**Foundation Models는 개발자가 모델을 호출하는 Apple 프레임워크/API 이름**이고, **AFM 3 Core Advanced는 이 Mac에서 실제로 반환된 모델 이름**입니다. 이 앱은 Swift Foundation Models로 AFM 3 Core Advanced를 호출하고, AFM 3 Cloud·AFM 3 Cloud Pro는 단축어 CLI로 연결합니다.

이 Mac에서 조회한 로컬 컨텍스트는 **8,192토큰**입니다. 파라미터 수와 한 번에 처리할 수 있는 문맥 길이는 다른 수치입니다. AFM 3 Core의 별도 호출 경로는 확인하지 못했으며, 모델군의 모든 기능이 현재 사용하는 공개 API로 노출된다고 가정하지 않습니다. 전사는 별도의 Speech API 경로로 시험했으므로 그 엔진 결과를 AFM 텍스트 생성 성능으로 합산하지 않습니다.

이 저장소는 AFM을 앱에 붙이는 실험용입니다. 바이브 코딩을 수행하는 코딩 에이전트 자체의 성능을 평가한 저장소는 아닙니다. 아래의 AFM 상세 시험 결과는 이 앱에서 실제로 관측한 별도 기록입니다.

## 주요 기능

- **진료 작업 화면**: 환자 목록, 진료 전 확인, 문진, 기록 검토, 환자 안내를 하나의 창에서 처리합니다.
- **초진 설문과 방문 관리**: 설문 제출, 검사 입력, 환자별 방문 연결과 과거 기록을 관리합니다.
- **음성 전사**: Apple Speech API로 한국어 마이크 입력과 기존 녹음 파일을 전사합니다. 임시 전사와 확정 전사를 구분해 표시합니다.
- **AI 초안**: 진료 전 참고, SOAP·CDSS 참고, 환자 안내 초안을 생성하고 항목별로 적용합니다.
- **모델 선택**: 로컬 LLM인 **AFM 3 Core Advanced** 또는 명시적으로 연결한 AFM 3 Cloud·AFM 3 Cloud Pro 단축어를 선택합니다. 실패 시 다른 모델로 자동 전환하지 않습니다.
- **편집과 복구**: 자동 저장, 수정 충돌 처리, 버전 이력, 초안 복구, 텍스트 가져오기·내보내기를 제공합니다.
- **Mac UI**: SwiftUI·AppKit, 시스템 툴바, Liquid Glass, Inspector, 파일 패널, 메뉴·단축키를 사용합니다.

기존 웹 화면과 환자용 웹 설문도 유지합니다. Notion 동기화나 카카오 메시지 자동 발송은 현재 기능에 포함되지 않습니다.

## 구조

```text
SwiftUI 네이티브 앱 / 기존 웹 화면
              ↓ localhost API
     Python 서버 · SQLite 저장소
              ├─ Swift Foundation Models → AFM 3 Core Advanced → 로컬 AI 초안
              ├─ shortcuts run → 선택한 AFM 3 Cloud / AFM 3 Cloud Pro
              └─ Swift Speech API → 파일·마이크 전사
```

전사 엔진과 텍스트 생성 모델은 서로 다른 API입니다. Speech 전사 결과를 AFM이 자동으로 교정하는 기능은 제공하지 않습니다.

## 개발 환경

현재 확인한 환경은 **Apple Silicon Mac, macOS 27, Xcode 27·Swift 6.4**입니다.

- 실행 가능한 Python 3: 서버는 표준 라이브러리를 사용합니다. Xcode 제공 Python으로 아래 검사를 통과하면 별도 설치는 필수가 아닙니다.
- Xcode 27 및 macOS 27 SDK
- 로컬 생성: Apple Intelligence와 Foundation Models가 사용 가능한 기기·설정
- 한국어 전사: SpeechTranscriber 사용 가능 상태와 한국어 모델
- 네이티브 마이크: 앱의 마이크 접근 허용
- 선택 사항: AFM 3 Cloud 모델용 단축어, DOM 시험용 Node.js·jsdom, 스트리밍 시험용 ffmpeg

개인 서명 인증서 지문·팀 ID는 공개 소스에 포함하지 않습니다. CLI와 Xcode는 Git에서 제외한 `macos/Signing.local.xcconfig`를 사용합니다. 자신의 Apple Development 인증서로 설정하며, 인증서와 비밀키를 저장소에 넣지 않습니다.

### 다른 Mac에서 테스트하려면

**현재 GitHub 저장소는 개발자용 소스입니다. Apple Silicon Mac에 macOS 27과 Xcode 27을 설치하고 직접 빌드하는 방식입니다.** Xcode 없이 바로 실행할 수 있는 독립 배포용 앱은 아직 제공하지 않습니다.

Xcode 27 설치만으로 모든 준비가 끝나는 것은 아닙니다.

1. Xcode의 초기 설정과 macOS 27 SDK 설치를 마칩니다.
2. 아래 서명 설정 절에 따라 자신의 개발자 인증서·팀을 로컬 파일에 지정합니다. 다른 사람의 인증서 비밀키는 필요하지 않습니다.
3. AI·전사 연결 프로그램의 빌드 스크립트가 사용하는 Command Line Tools·SDK 경로를 확인합니다. 현재는 별도 Command Line Tools 경로가 고정되어 있습니다. 해당 도구를 설치하거나 자신의 Xcode 도구·SDK 경로로 스크립트를 조정해야 합니다.
4. Python 실행 여부와 아래 회귀 검사를 확인한 뒤 DB·포트를 지정해 앱을 빌드합니다.

필요한 실행 구성 요소를 포함한 앱을 별도로 패키징하면 사용자는 Xcode 없이 실행할 수 있지만, 현재 저장소의 빌드 결과는 그 형태가 아닙니다.

### 권장: Xcode 27에 Codex 또는 Claude를 연결해서 진행하기

**처음 받아서 테스트한다면 Xcode 27을 설치하고, Xcode 안에 Codex 또는 Claude Agent를 연결해 함께 빌드·실행하는 방식을 권합니다.** 이 프로젝트도 Codex와 함께 만들고 Xcode에 연결해 빌드·검증했습니다. 개발 도구 경로와 서명 설정을 자신의 환경에 맞춰야 하므로 에이전트에게 조정을 맡기고 결과를 확인하는 방식이 편리합니다.

1. **Xcode 27 설치·초기 설정을 완료합니다.** macOS 27 SDK와 앞 절의 개발 도구 조건을 확인합니다.
2. **Xcode → Settings → Intelligence → Agents**에서 **Codex 또는 Claude Agent**를 선택합니다. `Get`·`Install` 안내에 따라 설치하고, 해당 에이전트의 계정 설정에서 로그인합니다. 일반 대화 모델을 켜는 `Chat` 항목과 빌드·테스트를 수행하는 `Agents` 항목을 구분합니다. [Apple 설정 안내](https://developer.apple.com/documentation/xcode/setting-up-coding-intelligence)
3. **저장소를 받은 뒤 `macos/ClinicMac.xcodeproj`를 엽니다.** scheme은 `ClinicMac`, 실행 대상은 `My Mac`을 선택합니다.
4. **Coding Assistant에서 연결한 에이전트를 선택합니다.** 먼저 저장소 루트의 `README.md`, `Agent.md`, `PRD.md`, `history.md`를 읽고 현재 환경과 미완료 항목을 파악하도록 요청합니다.
5. **자신의 Mac에 맞게 설정을 점검·수정하도록 요청합니다.** 서명 인증서·팀, Swift/SDK 경로, Python 경로, 시험용 DB·포트를 확인하고 빌드 오류를 해결합니다. 기존 DB는 보존하고 합성 자료로 시험합니다.
6. **빌드 → 실행 → 기능 시험 → 결과 확인 순서로 진행합니다.** 앱이 열리는 것뿐 아니라 설문 저장, 편집 복구, 전사, 모델별 초안의 실제 결과를 확인합니다. AI가 성공했다고 말한 것과 시험 근거를 구분합니다.

Xcode는 에이전트에게 빌드·테스트 기능을 제공합니다. 계정 연결과 사용할 모델은 Xcode에 표시되는 해당 제공자의 안내를 따릅니다. Codex의 ChatGPT 로그인과 API 키 로그인은 이용 방식이 다르므로 자신의 계정에 맞는 방법을 선택합니다. [Apple의 에이전트 소개](https://www.apple.com/newsroom/2026/02/xcode-26-point-3-unlocks-the-power-of-agentic-coding/), [OpenAI 인증 안내](https://learn.chatgpt.com/docs/auth)

**Codex·Claude는 앱을 개발·수정하는 도구이고, AFM 3는 이 앱에서 시험하는 모델입니다.** 개발 에이전트 연결이 앱의 생성 모델을 자동으로 바꾸지는 않습니다. 에이전트 사용 자체가 앱 실행의 필수 조건은 아니지만, 이 저장소의 권장 시작 방법입니다. 개발 에이전트가 프로젝트 자료를 외부에서 처리할 수 있으므로 실제 진료 자료 대신 소스와 합성 시험 자료로 진행합니다.

### Python 3는 macOS에 기본 포함되나요?

`/usr/bin/python3` 명령이 보이는 것과 macOS만 설치한 상태에서 Python 실행 환경이 준비된 것은 다릅니다. Python 공식 문서는 이 명령을 **Xcode 또는 Command Line Tools가 제공하는 개발 도구용 Python으로 연결되는 명령**으로 설명합니다. 따라서 macOS 27만 있으면 충분하다고 가정하지 않고, Xcode 설치 후 실제 실행 여부를 확인합니다. [Python 공식 macOS 안내](https://docs.python.org/3/using/mac.html)

```sh
# 현재 셸이 선택하는 Python
command -v python3
python3 --version

# Apple 개발 도구의 Python을 직접 확인
/usr/bin/python3 --version
/usr/bin/python3 -c 'import sys, sqlite3; print(sys.executable)'

# 저장소 루트에서 Apple 제공 Python으로 회귀 검사
/usr/bin/python3 -m unittest discover -s tests -q
```

2026-09-17 이 개발 Mac에서는 `/usr/bin/python3`가 Xcode의 **Python 3.9.6**으로 연결됐으며, 해당 실행 파일로 Python 회귀 **78개가 통과**했습니다. 기본 셸의 `python3`는 별도 Homebrew **Python 3.14.7**입니다. 이는 이 기기의 관측값이며 다른 Xcode 버전의 Python 버전까지 보장하지 않습니다. Apple Python으로 네이티브 앱의 전체 생성·전사 흐름을 다시 시험한 결과는 아닙니다.

**Xcode가 제공한 Python이 실행되고 검사를 통과하면 Python을 무조건 추가 설치할 필요는 없습니다.** 별도 Python을 선택했다면 빌드·실행에서 사용하는 경로를 일치시킵니다. 앱은 빌드 시 선택된 Python 경로를 `Runtime.json`에 기록하므로, 터미널의 `python3`와 앱의 Python이 다를 수 있습니다.

## 시작하기

저장소 루트에서 실행합니다. 기존 데이터가 있는 디렉터리를 사용하면 그 데이터를 그대로 읽습니다. 새 DB에는 샘플 환자를 자동으로 넣지 않습니다.

### 1. Apple 엔진 연결 프로그램 빌드

```sh
sh scripts/build_foundation.sh
sh scripts/build_speech.sh
sh scripts/build_live_speech.sh
```

위 세 스크립트는 현재 `/Library/Developer/CommandLineTools`의 Swift 컴파일러와 `MacOSX27.0.sdk` 경로를 사용합니다. Xcode만 설치한 다른 환경에서는 해당 스크립트의 도구·SDK 경로를 먼저 확인해야 합니다.

### 2. 네이티브 앱 빌드

먼저 자신의 개발 서명을 설정합니다. 복사한 로컬 파일은 Git에서 제외됩니다.

```sh
cp macos/Signing.local.xcconfig.example macos/Signing.local.xcconfig
security find-identity -v -p codesigning
```

`Signing.local.xcconfig`의 `CODE_SIGN_IDENTITY`에 위 명령에서 확인한 자신의 인증서 SHA-1을, `DEVELOPMENT_TEAM`에 자신의 Apple 개발 팀 ID를 입력합니다. CLI와 Xcode가 같은 파일을 사용합니다. CLI에서는 `CLINIC_SIGNING_IDENTITY`로 인증서를 명시할 수도 있습니다. 인증서가 없으면 빌드는 실패하며 임시 ad-hoc 서명으로 자동 전환하지 않습니다. 재빌드 사이에 같은 인증서와 bundle ID를 유지해야 macOS 권한을 유지하기 쉽습니다.

DB와 포트를 명시해 시험 DB가 우연히 선택되지 않도록 합니다.

```sh

CLINIC_NATIVE_PORT=8766 \
sh scripts/build_macos.sh
```

결과: `.build/native/한의원AI로컬구축.app`

Finder에서 앱을 실행합니다. 앱에는 빌드 시점의 프로젝트·Python·DB 경로가 기록됩니다. 따라서 `.app` 파일만 다른 Mac으로 복사해서 실행하는 독립 배포 방식은 아직 지원하지 않습니다. 서비스 시작이 필요한 경우 앱에서 로컬 서비스를 시작합니다.

## AFM 테스트 결과 — 2026-09-17

**결론: 연결과 생성은 되지만, 이 앱의 실전용 SOAP 품질 기준을 충족한 모델은 없었습니다.** AFM 3 Cloud Pro가 일부 입력에서 더 충실했으나, 전사 오류를 다루는 능력과 예측하기 어려운 사용 한도 때문에 상시 업무용 기본 모델로 삼기 어렵습니다. 지금은 macOS에서 로컬 LLM의 호출·응답·한계를 직접 시험하는 용도로 사용해 주세요.

### 무엇을 어떻게 시험했나

실제 환자 자료 대신 합성 문진 사례를 사용했습니다. 시험한 작업은 진료 전 참고 요약(가), SOAP·CDSS 참고(나), 환자 안내·처방 설명·메시지 초안(다)입니다. SOAP는 정확하게 작성한 대본(`gold`)과 Apple Speech가 실제로 전사한 문장(`ASR`)을 나누어 평가했습니다. 분할 시험에는 추가 호흡기 문답 사례(`holdout`)도 넣었습니다.

같은 버전·입력의 공통 프롬프트 해시를 맞췄지만 연결 방식은 다릅니다. 로컬은 Swift의 구조화 출력과 temperature 0.2, AFM 3 Cloud는 단축어의 출력 계약을 사용했고 AFM 3 Cloud 샘플링 설정은 제어하지 않았습니다. 따라서 아래는 **이 앱을 통한 모델 사용 결과**이며, 모델 자체만을 공정하게 분리한 대규모 벤치마크는 아닙니다.

내용 평가는 Codex가 대본·실제 입력·응답을 대조해 수행했습니다. 독립 임상의 평가나 통계적 정확도 검증은 아닙니다. 확인한 항목은 다음과 같습니다.

- 숫자·부정 표현·시간·한정어가 유지되는가
- 미검사·미측정·없음·미정·미확인을 구분하는가
- 환자 진술(S), 실제 검사·진찰(O), 평가(A), 계획(P)을 구분하는가
- 전사가 애매할 때 추정해 확정하지 않고 불확실성을 남기는가
- 입력에 없는 진단·처방·생활 지침을 추가하지 않는가
- 내부 프롬프트가 결과에 노출되지 않는가

### 3. SOAP 충실도 보강: 18회 생성과 품질 판정

기존 프롬프트 1회와 충실도 보강 프롬프트(`fidelity-v1`) 2회를 각각 gold·ASR 입력에 적용했습니다. 3모델 × 2입력 × 3회 = **18회** 모두 구조화 결과를 반환했습니다.

아래 시간은 모델별 6회 전체 평균이고, 내용 판정 열은 그중 **보강 프롬프트의 입력별 2회**를 뜻합니다.

| 모델 | 생성 결과·평균 시간 | gold 보강 2회 | ASR 보강 2회 | 주요 실패 |
| --- | --- | --- | --- | --- |
| AFM 3 Core Advanced | 6/6 · 25.0초 | 모두 실패 | 모두 실패 | 혈압 74/116 역전, 원문·지침 반복, ASR 반복에서 부정을 긍정으로 바꿈 |
| AFM 3 Cloud | 6/6 · 5.3초 | 모두 실패 | 모두 실패 | 처방 미정과 한약 처방 없음을 함께 출력, ‘모두 없어요’가 부정하는 증상 대상 누락 |
| AFM 3 Cloud Pro | 6/6 · 6.5초 | 해당 사례의 주요 충실도 기준 2/2 충족 | 모두 실패 | 애매한 ‘약 침’을 ‘약침’으로 확정. SOAP에서 확인 필요로 남겨도 다른 출력 필드에서는 단정 |

AFM 3 Cloud Pro의 기존 프롬프트는 정확한 대본에서도 ‘큰 외상 없음’을 ‘외상력 없음’으로 넓히고, ‘약·침 처방 미정’을 ‘없음’으로 바꿨습니다. 보강 프롬프트로 일부 오류는 개선됐지만 모든 필드에서 불확실성을 일관되게 유지하지 못했습니다.

**AFM 3 Cloud Pro의 gold 2/2는 이 한 사례의 제한된 통과입니다. 전체 SOAP 기능의 합격이나 실진료 정확도를 뜻하지 않습니다.** 근거: [history.md의 Q1](history.md#q1--afm-3-soap-충실도-비교).

### 4. 토큰을 줄이려고 SOAP를 나눠 보았나

실험했습니다. 원문을 문답 묶음으로 나누고, 묶음마다 **사실 추출 1회 → S/O/A/P 각각 1회 → 코드로 조립**하는 5단계 구조를 만들었습니다. 원문을 각 작성 단계에 함께 제공했으며 프롬프트·구현·실험·회고를 **4회 loop**로 수정했습니다.

| 회차 | 변경 | 결과 |
| --- | --- | --- |
| 1 | 사실 추출 후 항목별 작성 | 6회 모두 추출 출력과 검사 계약이 맞지 않아 실패. 모델의 임상 품질을 판단하기 전의 구현 문제 |
| 2 | 추출 결과를 네 문자열 필드로 구조화 | 로컬은 항목 혼입·혈압 누락, AFM 3 Cloud는 본문 형식 실패. AFM 3 Cloud Pro는 gold의 주요 사실을 보존했지만 ASR의 수치·용어를 추정 교정 |
| 3 | 해당 SOAP 항목의 메모만 제공, holdout 추가 | 로컬 S가 `{` 하나만 반환된 경우, 양성 증상을 모두 없다고 요약한 경우 발생. AFM 3 Cloud·AFM 3 Cloud Pro도 항목 혼입과 근거 없는 정보가 남음 |
| 4 | 출력 설명을 항목별로 맞추고 불완전 본문 거부, 반복 시험 | 후보 생성은 개선됐지만 세 모델 모두 전체 품질 기준 미달. AFM 3 Cloud Pro의 ASR 3회 모두 불확실성 보존에 실패 |

최종 버전과 추가 반복을 합친 결과입니다. 시간은 **문서 생성 시도 전체의 성공분 평균**이며, 5개 단계 중 한 번의 호출 시간이 아닙니다. 실패 시간은 평균에서 제외했습니다.

| 모델 | 생성 성공 / 시도 | 성공분 평균 | 최종 해석 |
| --- | --- | --- | --- |
| AFM 3 Core Advanced | 2/3 | 13.07초 | 지침 노출·부정 대상 누락·계획 누락. ASR 1회는 불완전 응답으로 거부 |
| AFM 3 Cloud | 3/3 | 14.64초 | 결과는 생성되지만 S/O/A/P 내용 혼입이 남음 |
| AFM 3 Cloud Pro | 8/9 | 11.03초 | gold 추가 2회와 holdout 성공 2회는 주요 사실 보존. gold 첫 회 의미 확대, ASR 3회 불확실성 처리 실패, 1회 단축어 실행 실패 |

누적 분할 시나리오는 **36회**, 추가 단일 생성 재비교 3회를 합쳐 **39회 시도**입니다. 39회의 개별 LLM 호출이라는 뜻은 아닙니다. 분할 한 묶음의 성공 경로만으로도 모델을 5번 호출합니다.

로컬 gold 성공 사례에서 단계별 입력은 758 / 882 / 882 / 821 / 859토큰으로, 합계 **4,202토큰**이었습니다. 이전 단일 생성 입력은 **1,053토큰**이었습니다. 한 번에 넣는 입력은 줄었지만 전체 입력량은 약 4배로 늘었습니다. AFM 3 Cloud의 실제 토큰 사용량은 제공되지 않아 비교하지 않았습니다.

따라서 **토큰 분할만으로 작은 모델의 의미 보존 능력이 해결되지는 않았습니다.** 짧은 입력에서도 오류가 있었으므로 모든 실패를 컨텍스트 부족 탓으로 볼 수 없습니다. 동시점 단일 생성 재비교 3회는 단축어 실행 실패로 끝나 분할의 우월성도 입증하지 못했습니다. 긴 무구조 문단과 묶음 사이 최신 사실·상충 내용 통합도 미완료입니다. 분할 생성은 시험 메뉴에 남겼으며 최선의 방법이나 기본 품질 개선으로 선언하지 않았습니다. 근거: [history.md](history.md)의 Q2~Q5.

### 5. AFM 3 Cloud Pro 사용 한도: 실제 업무에서 더 큰 제약

후속 시험에서 단축어가 **‘이 모델의 사용 한도에 도달했습니다. 나중에 다시 시도하십시오.’**를 반환했습니다. 앱도 이를 사용 한도 오류로 표시하고 기존 문서를 보존합니다.

2026-09-17 10:46 KST에 같은 합성 산술 입력을 모델별로 한 번씩 호출한 결과는 다음과 같습니다.

| 모델 | 결과 | 소요 시간 |
| --- | --- | --- |
| AFM 3 Cloud | `2` 응답, 정상 종료 | 1.690초 |
| AFM 3 Cloud Pro | 사용 한도 도달, 실패 종료 | 0.221초 |

확인한 것은 **AFM 3 Cloud Pro가 막힌 시점에도 AFM 3 Cloud 호출이 됐다**는 사실입니다. 두 모델의 한도가 완전히 독립적인지, 공통 상한도 있는지는 확인하지 못했습니다. 잔여량·정확한 초기화 시각·하루 가능한 SOAP 건수도 예측할 수 없습니다. ‘몇 번까지 쓸 수 있다’는 수치를 제시하지 않습니다.

특히 5단계 분할은 요청 횟수를 늘립니다. 중간에 한도가 걸리면 최종 후보를 만들지 못할 수 있으므로, 일부 좋은 응답만으로 AFM 3 Cloud Pro를 지속적인 진료 자동화의 주력으로 삼기 어렵습니다. 이전의 모든 단축어 실행 실패가 한도 때문이었다고 소급해서 단정하지도 않습니다. 근거: [history.md](history.md)의 S1~S2.

### 6. 각 모델을 어디에 써 볼 만한가

아래는 위 관측에서 도출한 **다음 실험 용도에 대한 판단**입니다. 강의·연구·행정 등 모든 영역을 따로 시험해 통과했다는 뜻은 아닙니다.

| 모델 | 시험해 볼 용도 | 현재 결과로 맡기기 어려운 일 |
| --- | --- | --- |
| AFM 3 Core Advanced | 짧은 합성 입력으로 로컬 호출·구조화 출력·UI 연결을 시험하기. 정답과 코드 검증 규칙이 있는 좁은 추출·분류 실험 | 긴 진료·회의 전사의 무검토 요약, 수치·부정·시점을 완전히 보존하는 기록, 복잡한 임상 추론, 장문 강의·연구 자료 종합 |
| AFM 3 Cloud | 사람이 원문과 대조할 수 있는 짧은 안내문·문장 정리 후보. 로컬 결과와 비교하는 기준 경로 | 다단계 판단을 사실처럼 기록하는 자동화, 여러 문서의 상충·최신 정보를 자동 확정하는 작업, 누락이 허용되지 않는 진료·행정 문서 |
| AFM 3 Cloud Pro | 정확하고 정리된 짧은 입력으로 품질 차이를 확인하는 소수 실험. 사람이 즉시 대조할 수 있는 초안 | 실시간 상시 업무, 대량·예약 자동화, 성공 시점과 처리량 보장이 필요한 작업, 오류가 섞인 전사를 자동으로 고쳐 확정하는 작업 |
| AFM 3 Core | 별도 호출 경로부터 확인해야 함 | 시험 근거가 없어 능력·적합성을 평가하지 않음 |

예를 들어 강의·독서 메모의 짧은 문장 다듬기는 후보를 눈으로 비교하는 실험이 가능하지만, 여러 논문의 근거를 정확히 인용·종합하는 연구 도구로 검증한 적은 없습니다. 행정 안내문 초안과 날짜·대상·금액을 틀리면 안 되는 자동 발송도 서로 다른 문제입니다. 후자의 결정적 값은 코드로 검증하고 발송 여부는 별도로 판단해야 합니다. 이 앱에는 외부 자동 발송 기능이 없습니다.

### 7. STT 결과를 AFM 능력과 혼동하지 않기

한국어 전사는 **SpeechAnalyzer + SpeechTranscriber**의 결과이며 AFM 텍스트 모델의 결과가 아닙니다. 동일한 85.67초 합성 음원을 Notion과 파일 업로드로 비교했을 때 Notion이 일부 용어에서 나았지만, 양쪽 모두 소변·압통·심부건반사·요통 등의 오류가 남았습니다. AFM이 그 오류를 추정해 자연스럽게 고치는 것은 원문 확인과 다릅니다.

소수 합성 사례·한 Mac·해당 날짜의 결과이며, 실제 환자 대화·장시간 전사·중첩 발화·독립 전문가 검증을 대체하지 않습니다. 원문과 모델 응답은 로컬 `.build/`에 보관하고 Git에는 넣지 않았습니다. 저장소의 시험 코드와 [history.md](history.md)의 집계·실패 기록을 함께 읽어 주세요. 이 README 정리 과정에서 모델을 새로 호출하지는 않았습니다.
